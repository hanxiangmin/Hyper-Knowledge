这是早期可审计示例。当前发布展示使用 39 节点、18 超边的新版案例，见 [`../sushi-local-preview/`](../sushi-local-preview/)。

本示例使用 [`source/sushi.md`](./source/sushi.md) 检验 Hyper-Knowledge `0.8.0` 的无向高阶知识图谱流程。它包含可审计的来源文档、规范化 bundle、校验回执和一个完全离线的交互工作台。

## 为什么使用超图

传记事件往往同时包含人物、时间、地点、作品、制度背景和参与角色。这里使用 `general/hypergraph`，把每个多方事件保留成一条原生无向超边，而不是拆成若干缺失上下文的二元事实。

晚年轨迹被拆成“贬谪惠州”“贬谪儋州”“北归”三条事件超边，分别直接连接原子化的人物、年份和地点节点。动作放在超边谓词中；`trajectory_index` 只记录年代顺序，不代表有向边。

## 三种展示方式

- **关联矩阵**：在元素很多时稳定查看节点与超边的精确成员关系。
- **关联聚焦**：选中节点后，只展示该节点及其所属超边；选中超边后，展示其全部成员和角色。
- **包络视图**：以成员数最多的关系簇为优先，使用规则圆/椭圆的包络布局；共享节点可以同时位于多个包络边界上。

包络支持点击、悬停隔离、拖动后规则形状重排和适配可见内容的重置。节点显示名位于圆内；同时属于多条超边的节点使用虚线外环提示。该 bundle 没有原生二元关系，因此不会出现二元投影页，也不会生成“投影辅助节点”。

## 可信边界

- 输入是一份用户提供的二手传记材料，尚未进行历史事实核验。
- 当前语义结构由 Codex 生成并标记为 `model_predicted`，不是人工金标准，也不是抽取准确率基准。
- 来源记录只证明某个说法出现在输入文档中，不证明该说法在历史上为真。
- 六张发布截图来自真实工作台并完成静态视觉检查；本示例不宣称已经穷尽所有交互路径的浏览器验收。
