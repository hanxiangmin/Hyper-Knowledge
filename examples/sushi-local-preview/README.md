# 苏轼：共享结构与成员角色展示案例

当前发布展示页是 [胶囊超边工作台](views/capsule-trial/workbench.html)：在同一张完整星图中，用带轻微阴影的胶囊表示超边，左侧编号、右侧名称。悬停超边时包络会填入浅色，选中超边会突出当前关系、成员和角色；选中节点则汇总它所属的超边。原 [菱形总览页](views/workbench.html) 保留供设计对比。验证范围见 [QA-capsule.md](QA-capsule.md)。

默认打开“全图总览”：39 个实体各出现一次，18 条超边以胶囊表示，65 条连线表示真实成员归属。共享节点位于内侧，高参与度节点突出显示；宽屏用规则椭圆展开整体结构。悬停或选择只强调相关部分，不删除其他节点，也不改变全图位置。

点击“逐条阅读”进入原有包络阅读器，查看选中超边，或逐条阅读选中节点所属的超边；“返回总览”回到全图。矩阵、关联视图和逐条包络视图仍保留。轨道仅辅助排版，不表示额外关系；距离和菱形大小不编码重要性。节点大小基于全图参与度，超边排名仍在阅读器中查看。

这是独立的高阶关联展示数据，不覆盖 `sushi-document-test`，不修改原始文档。它沿用原案例的独立实体 ID 和名称，用来源约束区分事件之间真正共享的人物、地点和政策。两个成员也可以构成超边；它们与更多成员的超边统一展示，不单独增加二元关系界面。

## 重建与打开

仅重建新的胶囊试验页，不覆盖旧总览：

```powershell
.\.venv\Scripts\hk.exe visualize examples/sushi-local-preview/bundle -o examples/sushi-local-preview/views/capsule-trial/workbench.html --view contour --no-open --json
```

以下是原预览数据的重建流程。当前渲染器已采用胶囊造型，重新生成旧路径也会使用新造型；如需保留对照，请使用上方独立路径。

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe examples/sushi-local-preview/build_preview.py
.\.venv\Scripts\hk.exe visualize examples/sushi-local-preview/bundle -o examples/sushi-local-preview/views/workbench.html --view contour --no-open --json
```

然后打开 `views/workbench.html`。本地 HTML 自带图数据，无需抽取模型或联网。脚本检查原文 SHA256 和每个证据行范围；如果生成文件已有不同内容，会停止而不是直接覆盖。复核差异后可显式使用 `build_preview.py --force` 重新生成此目录内的受管文件。

`build_preview.py` 中的 `RELATIONS` 是可读的、显式编排的知识包候选记录；脚本只规范化这些记录、复制原文、计算校验摘要，并调用正式 `validate_bundle`。这不是一次自动抽取能力评测，也没有声称已经由用户人工确认。

最终为 39 个独立节点、18 条超边、65 条成员关联，其中 4 条超边各含两个不同成员。书名号和完整专名保留在数据中；显示名称的简化不改动实体身份。未创建“年份＋动作＋地点＋阶段”的节点。

“苏黄并称”“苏辛并称”“宋四家之首”“寒食帖作者”均作为 `topology=hyperedge` 的双成员超边保留，并恢复黄庭坚、辛弃疾、宋四家和《黄州寒食诗帖》的原始实体 ID。成员数量不决定是否保留一条有来源支持的关系；没有补造第三个成员或将不同事实拼成一条超边。

源文件仍是原来的用户传记材料，SHA256 为 `65869e3042b4a3b7a83695f1a053f8a2d99a09d031167770d4636e433442c0ed`。材料可能含历史错误；这里的逐字证据只保证“文档如此叙述”，不保证历史事实准确。每条关系标记为 `editorial_candidate`（编排候选），并记录 `construction_method=editorial_source_mapping`、`review_status=pending_human_review`，不误称模型自动抽取或人工确认。对不确定日期的限制写入关系 `properties`，不伪造确定时间。

## 数据和验证

本次本地测试覆盖及限制见 [QA-reader.md](QA-reader.md)；已弃用圆阵列版的历史结果保留在 [QA.md](QA.md)。

新增全图总览的独立检查见 [QA-overview.md](QA-overview.md)。本地 manifest 使用 `presentation.overview_layout=radial_hypergraph`，只为此试验页增加默认总览，不覆盖原发布示例。

本地试验页启用 `presentation.contour_layout=single_hyperedge`：包络视图一次聚焦一条超边，可逐条切换，避免把全图拆成大量独立的小圆。共享实体沿用同一节点 ID，节点重要性与超边结构指标基于整个知识包计算，而不是只按当前局部的成员计数。图中尺寸和排序表达的是明确的结构指标，不代表历史地位、事实可信度或自动推断的重要程度。此布局仅为本地展示选项，其他视图和原示例仍保留。

- `source/sushi.md`：原文的逐字节副本。
- `bundle/`：正式 Bundle v1 表，含类型、角色、关系实例 ID、逐字证据跨度。
- `bundle/manifest.json`：原文及表文件 SHA256、统计、共享节点计数和限制。
- `validation.json`：正式 `showcase` 校验的完整结果；不等于浏览器视觉验收。
- `views/`：由主程序生成的本地交互页面，不由建模脚本绘制。

主题 `theme` 仅供布局和导航；`event_year` 只记录明确绑定的年份；`trajectory_index` 位于关系记录上。它们都不会把无向边变成有向边。不同事件拥有独立的稳定 ID，另有成员—角色—上下文摘要 `semantic_sha256`，短标题不作为事实去重键。
