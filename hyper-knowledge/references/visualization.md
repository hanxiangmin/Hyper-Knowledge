# Higher-order knowledge graph visualization

The offline renderer presents three lossless hypergraph representations within one Higher-Order Knowledge Graph Workbench. A fourth pairwise view is added only when the source bundle contains native two-node relations:

- `contour`: native membership-boundary view in which member nodes lie on their hyperedge boundary, shared nodes form boundary intersections, and non-shared members use balanced angular-gap spacing.
- `incidence`: native relation-node incidence view with explicit roles. A node selection first shows only that node and its incident native hyperedges; selecting one hyperedge then expands its complete member set.
- `matrix`: a stable node-by-hyperedge incidence matrix. Selecting a row, column, or cell highlights it without silently switching representation.
- `pairwise`: native two-node relations only. It never expands a hyperedge and never creates an auxiliary center.

The hypergraph representations are lossless display alternatives:

- `incidence` keeps relation nodes and role-aware node incidences explicit.
- `contour` uses deterministic membership-aware centers and adaptive rounded closed curves that pass through every member node. When no shared-node or spacing constraint requires deformation, the boundary approaches a circle and members are placed at near-even intervals. Shared nodes anchor the corresponding boundary intersections; other members are allocated across the remaining angular gaps. Selecting a shared node shows all incident hyperedges and their union of member nodes. Boundary intersection only means shared membership.

The initial contour layout treats the hyperedge intersection graph as a layout constraint. Hyperedges that share members are joined by a soft center-to-center spring so the shared node can sit on both boundaries. Hyperedges with no shared member repel one another and are separated whenever canvas space permits. This is a readability heuristic, not a semantic distance metric, and it may yield to dense or user-dragged layouts.

For an explicitly selected symmetric small-multiples alternative, set the bundle manifest's `presentation.contour_layout` to `symmetric_circles`. Each hyperedge occupies an equal-radius circle, ordered by descending member count in horizontally centered rows. Shared entities have linked display occurrences in their incident circles, not duplicated canonical records: preserve the same node ID, dashed shared-entity ring, and a visible linked-occurrence legend. Separate circles do not mean disjoint membership. A node selection retains its incident circles; a relation selection expands exactly its members. Dragging rotates that circle's evenly spaced member ring without distorting its boundary. Keep readable text and scrolling when all circles cannot fit. This mode is an opt-in presentation choice, not a mandatory replacement for the shared-boundary network; mixed pairwise bundles or visible isolated entities fall back to the membership-boundary layout so no data is silently omitted.

For one-at-a-time browsing, use `presentation.contour_layout=single_hyperedge`. Keep a navigable hyperedge list and display exactly the current relation's distinct members on one regular circle, without repeated cross-relation glyphs. Previous/next moves through the list; selecting an entity filters that list to its incident hyperedges, and Show all clears the filter. Keep the matrix and incidence views available for broader structure. Two-member hyperedges use opposite positions on the same circle and do not require a pairwise view. Dragging rotates the member ring. A list/filter context is presentation state, never a source-data transformation.

In this reader, expose interpretable global structural metrics instead of an unexplained importance score. Node degree counts distinct incident hyperedge IDs. Hyperedge member count counts distinct entities, shared-member count counts members with global degree greater than one, and adjacent-hyperedge count counts distinct other hyperedges sharing any member. Multiple roles for one entity must not inflate any of these counts. Equal primary metric values have tied ranks; deterministic tie ordering is not an additional importance claim. These metrics remain fixed across focus, language, theme, and filtering. If a universal hub makes adjacent-edge counts equal, retain that honest tie and offer member/shared-member sorting rather than inventing a discriminating score. Node area changes monotonically with degree between readable lower and upper bounds, while full names remain in tooltips and details. Enclosure size does not encode importance, and structural connectivity is not evidence quality, factual confidence, causality, or domain value.

Pack disconnected components independently, retaining isolated entities and endpoints of native pairwise relations. Use a central orbital layout only when the candidate node belongs to every hyperedge in that connected component, with at least three hyperedges. Never anchor a nonincident hyperedge to the dominant node. Arrange incident hyperedges in descending member-count order, clockwise from the top; the order is a readability convention, not a semantic ranking.

The dominant-node overview is circle-first. Use a regular circle whenever the number of visible hyperedges leaves enough angular room; otherwise use a regular oriented ellipse whose inner boundary passes through the central shared node. Expand the outer points toward the available canvas edges so a dense structure uses both width and height. Distribute exclusive members at near-even intervals around each circle or ellipse. Place additional shared members at numerical intersections of their regular boundaries whenever possible. If an exact regular intersection is unavailable or a node is dragged, use a broad local adjustment with distance-limited, tangent-continuous handles; do not create a pointed corner, overshooting loop, or self-intersection. Every actual member must remain on the rendered boundary. This geometric separation is a readability constraint, not an assertion that the relations are scientifically disjoint.

When exactly two visible hyperedges share one or more members, use the shared-boundary dual-lobe layout. Shared members lie on the central seam; exclusive members occupy opposite semicircular arcs. The two boundaries therefore meet at the true shared members instead of producing arbitrary overlapping loops. If a user drags a node, the boundaries still recompute from the edited display coordinates.

For dense overview scenes, keep every node visible. Render short atomic entity names inside adaptive circular node marks; wrap longer official names or titles inside the circle and retain the complete value in the tooltip and detail drawer. The compact glyph may remove one matching pair of decorative outer title or quotation marks (`《…》`, `〈…〉`, `“…”`, or `‘…’`) while preserving the canonical source label everywhere else; meaningful internal punctuation remains visible. This reduces detached-label collisions without deleting structure, shortening the stored value, or changing membership semantics.

Use a stable visual grammar across every representation. Entity names sit inside solid circular marks, while each native hyperedge or relation name uses a framed card in the same assigned hue as its enclosure boundary. Size entity circles primarily to fit their visible text; membership in additional native hyperedges may add only a small capped radius boost, never an unbounded degree-proportional bubble. Give nodes belonging to more than one native hyperedge a dashed outer ring, with the same cue repeated in the legend. Keep node and hyperedge marks name-only: type names, arity text, and membership-count subtitles belong in tooltips or the detail drawer, not below the primary name. A contour hyperedge uses one uniform solid-color boundary plus a very light fill; do not stack a gradient stroke, decorative dashed accent, and colored glow on the same relation. Use one fixed thick boundary width and do not expose a width selector. Increase boundary emphasis only on hover, selection, or linked focus. While one hyperedge fill, boundary, or title is hovered, tint its complete interior with a light version of the same relation color, keep that hyperedge and its complete member set crisp, and temporarily dim every unrelated node, relation, boundary, and pairwise link. Remove the tint immediately when the pointer leaves; hover state is display-only. Color supports the node-versus-relation distinction but never replaces the circle-versus-diamond shape cue.

Use an aspect-aware canvas while preserving circular glyphs and text proportions. Fit content bounds on first render, focus changes, window resize, and reset; reset also clears focus and drag overrides. On narrow screens, retain a readable minimum-width canvas and allow scrolling instead of shrinking the entire graph into tiny text. Center the initial graph scroll position; keep the matrix at its first row and column. Collapse an empty details drawer to a narrow rail and expand it after selection.

The pairwise view is conditional and source-faithful. It shows only assertions that already contain exactly two nodes, using an arrowless line and a nearby predicate label to explain why the nodes are related. A hypergraph-only bundle therefore omits this view entirely. Member roles for a hyperedge remain visible in the incidence view and in Relation Details & Sources.

When one relation is focused in the incidence view, place its native relation node at the center and arrange member nodes on an ellipse with reserved semantic sectors: people above, times to the left, places to the right, and all remaining collective, work, policy, event, or trajectory nodes below. Never reuse the people sector for an unclassified member; each member receives a distinct angular slot. This is a lossless radial incidence layout, not a star projection, because the center is the source relation itself. Resolve role-label collisions across the whole focused relation. If one relation repeats a role, append the member label to the role label so repeated `time` or `place` memberships remain distinguishable.

For a dense incidence overview, use the independent incidence matrix: rows are source nodes and columns are native relations. Group columns by declared theme and event year when supplied, and put shared entities before their related exclusive members. Preserve minimum row spacing and readable text with scrolling. A populated cell denotes membership; if the same entity has several roles in a relation, show all roles in its tooltip and accessible name. Column keys identify the original relation. Selection stays in the matrix; empty cells are not edges. The separate incidence representation uses a compact node-to-incident-hyperedge summary for high-degree nodes and expands members after one relation is selected. Neither representation creates pairwise projections.

The workbench supports Chinese and English UI copy without translating or mutating source node labels. Selecting a relation or any of its incidence links activates relation-induced focus: only that relation, its member nodes, and its own links or enclosure remain in the rendered structure. Selecting a shared node keeps every incident hyperedge and the complete union of their members at full opacity; no incident member may disappear merely because it was not the selected node. Node text is centered and wrapped inside its circle; relation labels remain rounded, category-coded blocks positioned independently from node marks.

Entity circles are draggable in graph representations; matrix rows and cells remain stable selection targets. Relation nodes are draggable in incidence view. In `contour`, dragging a member refits its incident circle or ellipse and redistributes members. Reject a refit that collapses or reverses the enclosure and restore a valid boundary position rather than accepting a broken shape. Clicking a fill, boundary, or title focuses the complete relation. Moving from a hovered relation to its own member retains that focus; keyboard activation retains a meaningful focus target after redraw. Display coordinates and focus never mutate source entities, membership, or evidence. Reset clears focus and drag overrides and restores the deterministic fitted view.

Clicking a node, relation, hyperedge, or incidence opens Relation Details & Sources. Raw topology and epistemic-status codes are translated into readable terminology and accompanied by short explanations. Source records show the exact source path, line range, and excerpt when available. When a bundle lacks source spans, the panel may show properties, member roles, and method status, but it must not claim source-span evidence.

The exported HTML is self-contained and does not load JavaScript, fonts, analytics, or other assets from a CDN. It supports Chinese/English UI switching, light/dark themes, deterministic layouts, pan/zoom/reset, relation-induced focus, linked selection, direct edge-role labels, low-emphasis single-stroke enclosure rendering, and a structured relation-and-source detail panel.

`view-manifest.json` records the bundle ID, initial view, available representations, pairwise-view availability, validation summary, layout seed, output hash, and `visual_review`. Rendering is written through a same-directory candidate and replaces the target only after deterministic validation succeeds.

Do not merge the following claims:

- Bundle validation proves structural and hash checks.
- Browser evidence proves named viewports and interactions were exercised.
- Perceptual review judges clarity and polish. It remains `pending` until a human or image-capable reviewer actually inspects the output.

For large graphs, filter or aggregate before rendering. Do not interpret layout distance as scientific or semantic distance unless the selected layout explicitly defines that meaning.
