# 实体、事件与角色

Hyper-Knowledge 的建模重点是：**让同一件事的参与者、条件和来源仍然属于同一条关系。** 超边的价值不在于画了一个大圈，而在于圈所表达的共同语境可以被检查。

## 节点回答“是什么”

人物、地点、时间、作品、机构适合成为可复用实体。名称应能单独指认对象，类型用于说明它是什么，标识符用于区分同名对象。

以仓库案例为例，“1101 年北归常州阶段”不应是一个复合节点：

| 放在哪里 | 内容 | 原因 |
| --- | --- | --- |
| 人物节点 | 苏轼 | 可参与多件事 |
| 时间节点 | 1101 年 | 可与其他事件复用或对照 |
| 地点节点 | 常州 | 保持地点身份独立 |
| 超边谓词 | 北归 | 表达发生的事情 |
| 成员角色 | 北归者、时间、到达地 | 解释各节点在该事件中的作用 |

这是案例数据的组织方式，不是对历史事实的新断言。

## 超边回答“哪件事把它们联系起来”

三苏家族、科举考试、乌台诗案是不同语境。即使它们包含同一个人物，也不能因此合并成一条大关系。

一条超边至少需要明确的谓词、成员集合和可解释的成员角色。成员之间不必互相构成同一种两两关系；例如“时间”和“主考官”只是共同参与科举事件。

## 角色回答“以什么方式参与”

角色属于**成员关联**，不属于人物永久属性。苏轼可以在考试中是“考生”，在另一条超边中是“被控者”或“治理者”。

同一条关系有多个地点或年份时，先判断是不是混合了多个事件：

- 若是不同经历，拆成独立事件超边，并共享人物节点。
- 若确实是一个事件的多个时间点，明确“开始时间”“结束时间”等角色。
- 若来源没有解释对应方式，保留不确定性，不自行配对。

苏轼案例把晚年经历拆成“贬谪惠州”“贬谪儋州”“北归”，避免一条关系里多个年份和地点失去对应关系。

## 共享节点不等于新的事实

“苏轼同时出现在 18 条超边中”是成员计数。节点在画面中居中、圆圈变大、包络相交，都不是额外知识断言。拖动与缩放只改变阅读方式。

显示名称可以移除作品名外层的书名号以节省空间，原始标签仍保留在数据和详情中。需要区分同名作品、版本或作者时，应完善标识与属性，而不是随意截断名称。
